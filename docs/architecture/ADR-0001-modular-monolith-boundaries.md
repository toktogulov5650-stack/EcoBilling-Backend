# ADR-0001: границы модульного монолита

- Статус: принято
- Дата: 2026-09-24

## Контекст

EcoBilling обслуживает один округ и разворачивается как API и Worker с общей локальной PostgreSQL. Бизнес-функции должны оставаться в одном процессе и репозитории, но иметь проверяемые границы.

## Решение

Используется модульный монолит со следующим разрешённым production-графом:

```text
Api -> Infrastructure
Api -> Modules
Worker -> Infrastructure
Worker -> Modules
Infrastructure -> Modules
Infrastructure -> SharedKernel
Modules -> SharedKernel
SharedKernel -> ничего
```

`Api` и `Worker` являются composition roots. `Modules` содержит бизнес-правила и не зависит от способов запуска или инфраструктуры. `Infrastructure` реализует технические интерфейсы модулей. `SharedKernel` содержит только небольшие общие примитивы.

Фактический граф загружается из `EcoBilling.slnx` и `ProjectReference` каждого включённого `*.csproj`. ArchitectureTests отклоняют незарегистрированное направление и циклическую зависимость.

## Последствия

- Границы проверяются при каждом запуске тестов, а не только документируются.
- Новое направление зависимости требует отдельного архитектурного решения.
- Общий тип добавляется в SharedKernel только при наличии практического потребителя в нескольких модулях.
- Микросервисное разделение и дублирование бизнес-логики в Worker не допускаются.
