# ADR-0007: граница профиля Controller

- Статус: принято
- Дата: 2026-09-25

## Контекст

Контроллеру нужен отдельный профиль, связанный с Identity. Назначения адресов или маршрутов и правила доступа к жителям пока не утверждены и зависят от будущей модели Addresses.

## Решение

- `Controller` хранит только идентификатор профиля, `UserId`, полное имя и время создания.
- Профиль связан отношением один-к-одному с `identity.user_accounts` через обязательный уникальный внешний ключ.
- Доменная фабрика принимает `UserAccount` и разрешает создание профиля только для роли `Controller`.
- Для полного имени утверждены только обязательность и удаление внешних пробелов. Формат, составные части, длина и допустимые символы не предполагаются.
- Получение профиля выполняется по `UserId`; HTTP endpoint и механизм текущего пользователя не входят в этот этап.
- Persistence использует schema `controllers` и таблицу `controllers.controllers`.
- Удаление Identity при существующем профиле запрещено правилом `Restrict`.
- Назначения адресов/маршрутов, offline-режим, заметки и доступ к жителям в профиль не добавляются до утверждения соответствующих правил.
- Сценарий создания контроллера директором, первичный пароль и аудит отложены до появления согласованного application-сценария.

## Последствия

- Профиль Controller можно получать и сохранять независимо от будущей модели назначений.
- Одна Identity не может иметь более одного профиля Controller.
- Соответствие роли проверяется доменной фабрикой; прямые административные SQL-изменения считаются обходом доменных инвариантов.
- Наличие роли Controller само по себе пока не предоставляет доступ ни к одному Resident.
