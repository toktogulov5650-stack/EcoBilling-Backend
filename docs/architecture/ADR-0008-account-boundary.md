# ADR-0008: граница лицевого счёта

- Статус: принято
- Дата: 2026-09-25

## Контекст

Лицевой счёт нужен как самостоятельная бизнес-сущность, связанная с Resident. Формат номера, кардинальность связи Resident-Account, модель адреса и правила финансового состояния пока утверждены не полностью.

## Решение

- `Account` хранит идентификатор, `ResidentId`, обязательный `AddressId`, канонический номер лицевого счёта и время создания.
- Номер обязателен и нормализуется как `Trim + ToUpperInvariant`.
- В PostgreSQL хранится только канонический номер; по нему действует уникальный индекс в границах одного экземпляра округа.
- Профиль Account обязательно ссылается на существующий Resident через внешний ключ с `RESTRICT`.
- Уникальность `ResidentId` не вводится: допустимость нескольких лицевых счетов у одного Resident остаётся открытым решением.
- `Balance`, долг и переплата не хранятся до утверждения источника истины и разрешённых операций изменения финансового состояния.
- Получение Account выполняется по нормализованному номеру; HTTP endpoint и авторизация не входят в этот этап.
- Persistence использует schema `accounts` и таблицу `accounts.accounts`.
- Адрес обслуживаемого объекта связан с Account по ADR-0009 и не хранится в профиле Resident.

## Последствия

- Номер лицевого счёта имеет одинаковую каноническую форму в Identity и Accounts.
- База отклоняет повторный канонический номер и ссылку на отсутствующего Resident.
- Схема не навязывает неподтверждённую кардинальность Resident-Account.
- Финансовые значения не могут изменяться прямым редактированием поля Balance, которого пока нет.
- Удаление связанного Address запрещено внешним ключом с `RESTRICT`.
