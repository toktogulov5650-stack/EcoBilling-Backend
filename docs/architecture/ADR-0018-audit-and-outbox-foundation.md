# ADR-0018: аудит и инфраструктурная основа Outbox

- Статус: принято
- Дата: 2026-09-27

## Контекст

Административные и финансовые изменения должны оставлять аудит, а надёжная публикация
событий должна использовать Outbox только там, где действительно появляется внешний
асинхронный эффект. На текущем этапе единственный завершённый административный сценарий
изменения данных — внутренний provisioning первого директора. Для него ADR-0017 требует
аудит, но явно не требует Outbox: контракт локальный и синхронный.

Автоматическое копирование всех EF Core изменений в аудит опасно: оно не знает
пользовательского смысла действия, может сохранить password hash или персональные данные
и не имеет надёжного actor context.

## Решение

- AuditLog и OutboxMessage являются техническими типами EcoBilling.Infrastructure;
  бизнес-модули от них не зависят.
- Обе таблицы находятся в schema infrastructure.
- AuditLog хранит actor type/id, устойчивое имя действия, тип/id объекта,
  опциональные JSON-снимки, correlation ID и UTC-время.
- AuditLog append-only: публичных операций изменения нет, а EcoBillingDbContext
  отклоняет tracked update/delete. Ограничение доступа к таблице отдельной PostgreSQL-ролью
  остаётся задачей production-развёртывания.
- Успешное создание директора записывает действие identity.director.provisioned в той же
  PostgreSQL-транзакции, что UserAccount, DirectorProfile и DirectorProvisioningOperation.
- Actor ID берётся только из уже проверенного JWT issuer внутреннего сервиса;
  correlation ID берётся из HTTP trace identifier.
- JSON результата provisioning содержит только directorId, userId и operationId.
  Имя, email, пароль, password hash, fingerprint и idempotency key в аудит не попадают.
- Идемпотентный replay не создаёт вторую запись аудита.
- Outbox хранит id, type, JSON payload, occurred/processed UTC-время, retry count и
  последнюю ошибку. Модель поддерживает явные переходы failed/processed.
- На этом этапе ни один сценарий не создаёт OutboxMessage, publisher/dispatcher,
  hosted service и расписание не регистрируются. Первый реальный producer должен записывать
  сообщение в одной транзакции с бизнес-изменением после утверждения внешнего контракта.

## Последствия

- Provisioning директора имеет минимальный безопасный административный аудит без утечки
  учётных данных.
- База готова хранить будущие Outbox-сообщения, но не создаёт ложных событий и не обещает
  неподтверждённый транспорт.
- Политика хранения аудита, PostgreSQL-права append-only, batch size, lease/locking,
  backoff, dead-letter и конкретные обработчики остаются открытыми до появления реальной
  интеграции.
