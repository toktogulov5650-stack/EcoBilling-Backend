# ADR-0022: граница End-to-End тестов

- Статус: принято
- Дата: 2026-09-28

## Контекст

План первой волны E2E включает вход трёх ролей, создание жителей и контроллеров, назначения, показания и пользовательское чтение счетов, начислений и платежей. Однако текущий production API предоставляет только health endpoints и защищённый внутренний контракт создания первоначального директора. Пользовательская HTTP-аутентификация, выпуск токенов и остальные mutation/query endpoints ещё не спроектированы, а часть зависимых бизнес-правил остаётся открытой.

Добавление фиктивных endpoints или пропущенных тестов с выдуманными контрактами создало бы ложное покрытие и нарушило бы правило не подменять неподтверждённые решения случайными значениями.

## Решение

- `EcoBilling.EndToEndTests` проверяет только существующие завершённые HTTP-сценарии.
- Каждый E2E-тест использует настоящий ASP.NET Core pipeline через `WebApplicationFactory`, настоящую PostgreSQL и отдельную временную базу данных.
- Перед сценарием к чистой базе применяются все EF Core migrations; после сценария база удаляется.
- Строка административного подключения поступает только через `ECOBILLING_TEST_POSTGRES_CONNECTION` и не хранится в репозитории.
- Первый provisioning journey проверяет весь путь Control → JWT authentication → HTTP endpoint → application handler → PostgreSQL → audit:
  - запрос без service token получает безопасный `401`;
  - авторизованный запрос создаёт директора;
  - correlation ID проходит через ответ и аудит;
  - initial credential отсутствует в ответе и аудите и хранится только как hash;
  - повтор с новым одноразовым JWT и тем же `Idempotency-Key` возвращает тот же результат без дубликатов.
- Второй journey фиксирует отсутствие публичной регистрации: в endpoint inventory разрешены только health и internal routes, а попытка HTTP-регистрации получает безопасный RFC 7807 `404` без отражения переданных данных.
- Не реализованные HTTP-сценарии перечисляются в явной матрице покрытия. Для них не создаются `Skip`-тесты и placeholder endpoints.

## Последствия

- E2E-проект больше не является пустым и автоматически выполняется общим `dotnet test` в CI, где этап 18 поднимает PostgreSQL service.
- Локально без `ECOBILLING_TEST_POSTGRES_CONNECTION` E2E-тесты пропускаются с явной причиной.
- Покрытие входа пользователей, ролей, назначений, показаний, начислений и платежей будет добавляться вместе с утверждёнными HTTP-контрактами и бизнес-сценариями.
- In-process HTTP host не заменяет отдельный container smoke test; сборка контейнеров остаётся самостоятельным CI-gate.
