# ADR-0024: финальная проверка безопасности и готовности

- Статус: принято
- Дата: 2026-09-28

## Контекст

Техническая основа проекта собиралась, тестировалась и документировалась поэтапно, но успешная сборка сама по себе не доказывает готовность production. Требовалось проверить зависимости, секреты, входную конфигурацию, логирование ошибок, CI supply chain и контейнерный контур, а затем явно отделить устранимые дефекты репозитория от решений конкретного окружения.

## Решение

- NuGet audit включается централизованно для прямых и транзитивных зависимостей с уровнем `low`.
- Сторонние GitHub Actions закрепляются полными commit SHA; ArchitectureTests не допускают возврат к movable version tags.
- API использует явный allowlist `AllowedHosts`; wildcard запрещён тестом, а Compose требует значение окружения.
- Worker журналирует тип необработанной ошибки, но не объект исключения и не потенциально чувствительное сообщение.
- Результат security/readiness review хранится в отдельном [руководстве](../security/README.md) с доказательствами, остаточными рисками и release blockers.
- Текущее production-решение — NO-GO до закрытия инфраструктурных блокеров. Успешные тесты разрешают development/integration/staging, но не отменяют это решение.

## Последствия

- Ошибки supply-chain pinning, NuGet audit и host filtering становятся исполняемыми регрессиями.
- Окружение должно явно передавать допустимые host names и не может незаметно принять wildcard из Compose.
- Диагностика Worker сохраняет классификацию ошибки, но подробности исключения доступны только через безопасный механизм диагностики вне стандартного production-лога.
- Владельцы эксплуатации должны закрыть secret store, PostgreSQL roles, TLS/proxy, backup/restore, observability и container vulnerability policy до production release.
- Обнаруженные CVE базовых/служебных образов не маскируются успешной сборкой и требуют обновления, VEX либо формального risk acceptance.
