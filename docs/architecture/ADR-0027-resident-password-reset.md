# ADR-0027: сброс пароля Resident директором

- Статус: принято
- Дата: 2026-09-29

## Контекст

Resident не меняет пароль самостоятельно. Директору нужен безопасный повторяемый сценарий восстановления доступа без передачи старого пароля и без сохранения открытых credentials.

## Решение

- Director устанавливает новый пароль через `PUT /api/v1/residents/{residentId}/password`.
- Команда требует `Idempotency-Key`; одинаковый ключ и запрос возвращают исходный результат, а другой запрос с тем же ключом завершается конфликтом.
- Новый пароль проверяется общей политикой 12–256 символов и хешируется до persistence.
- Смена hash, снятие lockout, отзыв всех refresh-сессий Resident, запись операции и Audit выполняются одной PostgreSQL-транзакцией.
- Пароль, hash, номер лицевого счёта и refresh tokens не записываются в Audit или ответ API.
- Уже выпущенный stateless access JWT не может быть отозван текущей моделью и остаётся действительным не дольше настроенного срока, по умолчанию 15 минут. Новый refresh после сброса по старой сессии запрещён.

## Последствия

- После сброса старый пароль и все ранее выданные refresh tokens не работают; новый login создаёт новую token family.
- Для немедленного отзыва access JWT потребуется отдельное версионирование credentials или deny-list с проверкой при каждом авторизованном запросе.
- Сброс credentials Controller/Director остаётся отдельным сценарием: эта операция технически и доменно принимает только Resident.
